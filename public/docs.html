Trends v4.3.4

  • trend is number | null. null means “there is no comparison worth making” — it is not the same claim as 0 / “flat”. A percentage is published only when a baseline exists, is not zero, and is at least 10 for counts/sums/levels/averages. Rates keep their own scale.
  • trendBasis says what is compared: second-half-vs-first-half (the same selected range split in two) · last-day-vs-first-day (gauges) · window-edges (YouTube subscribers) · previous-window (GSC only — the one real period-over-period number). trendWindows carries the exact ISO dates behind it.
  • previous = the baseline the trend was computed against (first half, or first day for a gauge).
  • direction is up | down | flat | null.
  • For position, a falling number is favourable — the dashboard inverts the colour.
  • A trend was never “vs yesterday” or “vs last week”. The dashboard therefore prints no percentage on the top metric cards: a card shows the number and its sparkline, and the metric table shows comparisons labelled with their basis.

Stages — first match wins

stageConditionWhat it means
unreachablethe payload carries errorFix the connection first — every number is missing, not zero. The funnel reads not read and there is one explanation, not one per card.
no-contentpost count is a known 0Cadence is the whole problem.
pending-lagPinterest/LinkedIn, reach 0, items younger than 48 hReporting has not caught up. Resolves on its own.
not-reported v4.3.1Pinterest: every post is known upstream (real pin id + URL, syncStatus "synced"), every metric is 0, at least one post is past the 48 h lag, and the account gauges (pin count, board count, monthly views) are all emptyThe platform is not measuring this account. Pinterest serves organic analytics to Business accounts only, so 0 here is a missing entitlement — not a verdict on the content. Convert the account (free) and reconnect it.
no-distributionpublished, reach 0The algorithm is not serving it. Creative polish cannot fix this.
seen-not-engagedreach > 0, engagement 0Hook, format or call to action.
engaged-not-followedengagement > 0, follower growth 0No reason to come back — publish a series.
no-conversionengagement > 0, clicks 0Attention with no path to a destination.
healthythe whole funnel movesScale the format that produced it.

An unknown post count (published: null — Search Console has none, and a denied posts endpoint has none) is never reported as idleness: it falls through to the reach test and the headline says the count was not reported.

data.focus — where to spend this week (/api/combined)

[ { "platform": "linkedin", "stage": "no-distribution", "headline": "…", "score": 4.5,
    "audienceFit": "high", "audienceWhy": "…",
    "firstAction": "Fix distribution before creative",   // a string, safe to print
    "firstActionDetail": "…" } ]

score = STAGE_WEIGHT × FIT_WEIGHT, descending:

STAGE_WEIGHT  unreachable 3.2 · no-distribution 3 · no-content 2.6 · seen-not-engaged 2.2 ·
              no-conversion 1.8 · engaged-not-followed 1.6 · healthy 1.2 · pending-lag 0.8
FIT_WEIGHT    high 1.5 · medium 1 · low 0.6

So a blocked channel that reaches your target audience outranks a healthy one that does not — the opposite of ranking by follower count. Fit for institutions: LinkedIn / Search Console / YouTube high, Facebook medium, Instagram / Pinterest low. For students: Instagram / YouTube high, Pinterest / LinkedIn / Search Console medium, Facebook low.

Benchmarks are references. The figures in BENCHMARKS are published 2026 education-niche numbers (Hootsuite, Socialinsider, Quid/Rival IQ, SociaVault Labs, Sprout Social Index). They are context for a small account, never this account's data, and every surface that prints them says so.

One-call diagnostic report — GET /api/report v4.3.1

One URL that returns every output the API can produce, plus the evidence behind it. Built for the case where a number looks wrong and the question is “did the platform say 0, or did we lose it?” — which can only be answered from the verbatim upstream body.

GET /api/report?days=90                 # everything, redacted JSON (~600 KB)
GET /api/report?days=90&format=text     # paste-able digest (~15 KB)
GET /api/report?sections=probes         # just the Pinterest / LinkedIn verdicts
GET /api/report?raw=false               # transformed payloads only
SectionContents
configAPI + dashboard version, node, port, the dashboard bundle hash, which env vars are set (as {set,length,preview} — never values), endpoint overrides, unexpected env vars
healthThe same object /api/health returns
platformsAll six payloads exactly as their endpoints return them, with per-channel read timings
diagnosisdata.diagnosis.{institutions,students}.{channel} — both audience targets in one call
combinedThe focus ranking for both audiences
rawVerbatim upstream bodies: Meta Graph (page, posts, insights, IG profile, IG media, one media-insight call), Google Search Console (token, sites, one query), YouTube (token → Data API → Analytics, step by step), Zernio (accounts doc, /v1/analytics per platform, follower stats, both board paths)
probesA written verdict per Zernio channel: connected? analytics enabled? how many posts upstream? how many carry metrics? how old is the oldest? is this an entitlement gap?

meta carries tookMs, per-section timings, bytes, truncations (every capped list is listed), redacted: true and cacheBypassed: true. Sections are collected in parallel; one failing section never fails the report — it appears in errors[] with its own message.

Redaction contract. Nothing secret leaves the process. Credential keys are masked as [redacted N chars XX…]; a credentials object (byokCredentials) is masked whole; a URL keeps its readable part with any access_token= query parameter replaced; an expiry date survives because it is a fact, not a credential; lists are capped at 60 items and every cap is reported. A call recorded under a label that merely mentions a token (“page token exchange”) keeps its evidence.

From a terminal, against any deployment (works even if that deployment is older than 4.3.1 — the script falls back to collecting endpoint by endpoint):

npm run report -- --api https://your-api.onrender.com --days 90 --out report.json

Getting Search Console credentials

  1. Google Cloud Console → new project (or existing).
  2. Enable the Google Search Console API.
  3. Create an OAuth 2.0 Client ID (Web application); add https://developers.google.com/oauthplayground as a redirect URI.
  4. OAuth Playground → ⚙️ → use your own credentials.
  5. Scope: https://www.googleapis.com/auth/webmasters.readonly → Authorize → Exchange → copy the refresh token.
  6. Verify your property in Search Console, then set GSC_SITE_URL. /api/gsc lists every verified site in meta.verifiedSites.

Troubleshooting

SymptomCauseFix
Facebook / Instagram → 400Expired token, wrong page or IG id, missing pages_read_engagement / instagram_manage_insightsNew long-lived Page token → restart. /api/health returns the exact steps.
Instagram shows 0 likes / comments although the posts have themThree causes, all proven from a live /api/report: (1) Meta answers the metric_type=total_value + period=day combination with an empty 200 — no error, no rows; (2) /{ig-id}/media is refused with (#36104) … outside of the Business Discovery API, so per-post counts were unreachable; (3) the post count was then reported as 0, which made the diagnosis claim “nothing was published”.All three are handled: every insights form is tried in turn (meta.insightVariants records which one answered, and a metric empty in all forms lands in partialErrors + notice); the media list falls back to business_discovery.username(…){media{…like_count,comments_count}} (meta.postsSource); and meta.postCount becomes null (unknown) rather than 0, with meta.mediaCountLifetime beside it.
Facebook has no Comments / Shares cardMeta retired page_post_engagements breakdowns for many Pages, so those cards are summed from the Page posts — and a summed zero used to be dropped instead of shown.Fixed: a measured zero is rendered (“0 · summed from 9 posts”). Metrics the post endpoint does not expose at all (Facebook impressions, saves) are still never invented, because each mapper declares analyticsProvided.
Pinterest metrics all zeroMost often an entitlement gap: Pinterest serves organic analytics to Business accounts only. Confirmed on a live account 2026-10-21 — 6 pins, each with a real pin id + URL and syncStatus "synced", every metric 0, the oldest 32 days (far past the 24–48 h lag), and pinCount/boardCount/monthlyViews/accountType all empty.Convert the Pinterest account to a free Business account (Settings → Account management → Convert to business), reconnect it in Zernio after converting, then re-check. Do not re-authorise for scopes: the live capture shows the connection already holds pins:read, boards:read and user_accounts:read with platformStatus:"active" — the missing piece is the account type, and the API says so in notice and in the diagnosis action. GET /api/report?sections=probes states which case you are in; data.diagnosis.stage is not-reported and the API says “not measured” rather than blaming the content.
LinkedIn metrics tiny but realPersonal profiles publish impressions but no follower count, and reach stays small until cadence exists (a live 90-day capture: 8 posts, 93 impressions, 2 likes).The diagnosis adds lowReach and ranks “fix reach before anything else” first. Nothing is broken upstream.
YouTube shows "YouTube Channel", 0 subscribersRefresh token lacks youtube.readonlyAdd the scope. Analytics keep working without it.
GSC position 0.00No impressions in the windowExpected — rendered muted with a note.
